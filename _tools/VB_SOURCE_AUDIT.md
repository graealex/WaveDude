# Audit: original VB source (`2D_wave_sim_V01/`) vs the C# port (`Wave_Dude_2D/`)

Date: 2026-10-08. **Status: acted upon the same day.** The reasoning comments, doc corrections,
constant unfolds, local renames and the behaviour restorations in "Semantic differences (accidental)"
have been applied to the C# (see CLAUDE.md, "Fixed on 2026-10-08"). Deliberately not applied: the
GPL/attribution headers and `AssemblyCopyright` (the C# tree is temporary), and the decompiler
artefacts listed under "cosmetic". The line numbers below are from before those edits.

Read-only comparison of every VB file against its C# counterpart(s), looking for
what decompilation strips (comments, XML docs, local names, folded constants, `Debug.Assert`,
conditional code) and for behavioural drift. Line numbers refer to the files as they were on that date.

## Headline findings

1. **The VB source is newer than the binary that was decompiled.** The source has a GPL-3.0-or-later
   header on 31 of 38 files, `AssemblyCopyright("Copyright © 2026 JJM Vleggaar (Huygens Optics)")`,
   and a Help-tab disclaimer that says "free software, released under the GNU General Public License,
   version 3 or later". The decompiled Help text (`HelpForm.cs:32`) still says "educational use only.
   Redistribution for commercial purposes is not allowed", and `Properties/AssemblyInfo.cs:13` has
   `"Copyright ©  2026"` with no author. Every other Help paragraph is string-identical, so the author
   relicensed and added headers after that build. The header text refers to "the LICENSE file that
   comes with the source code"; no LICENSE/COPYING file is in `2D_wave_sim_V01/`.
2. **Provenance lost.** Five files (`WaveSimulator`, `GpuWaveSimulator`, `FrameRenderer`, `SceneData`,
   `ColorLut`) carry "Portions of this file are based on WaveSimulator2D by 0x23
   <https://github.com/0x23/WaveSimulator2D>". That repository is Python/CuPy and has no licence file
   (checked 2026-10-08), so the note is the author's attribution, not an inherited obligation. The C#
   docs also dropped every reference to the Python original (`main_curr.py`, `WaveVisualizer.render_field`
   / `render_intensity`, `get_colormap_lut`, `StaticImageScene` / `StaticRefractiveIndex` /
   `StaticDampening`, matplotlib `_r` maps), which is where several magic numbers come from.
3. **Code is faithful.** No logic bug was introduced by decompilation. The divergences found are listed
   under "Semantic differences"; all are small, and most are deliberate post-decompile fixes.
4. **Two CLAUDE.md "known issues" are wrong.** The differing `FromConfig` fallbacks and the
   `Use4thOrderLaplacian`/`WaveSpeedC` defaults are documented by the author as deliberate
   old-project compatibility (see `SimulationSettings.vb:47-49, 92-103, 106-119`). The GpuWaveSimulator
   `TryCreate` doc in the VB overstates its own code, which is the root of the "dead branch in
   `WaveEngineFactory.Create`" entry.
5. **What was stripped**: 1,409 lines of `'''` XML docs and 1,242 `'` comments in the VB. The C# docs
   were written fresh and are often more complete on threading and layout, but the author's *rationale*
   (why a formula, why a workaround, why a default is absent) is largely gone. Roughly 150 comment sites
   are listed below with the C# location they belong at. Nothing else was stripped: the VB has no
   `#If` blocks, one `Debug.Assert` (kept), no `Obsolete`, no `Static` locals, and all `Optional`
   defaults survived.

- ClickOnce publishing (`PublishUrl ...\2D_wave_sim_install_V0.29\`, `ApplicationRevision 18`), manifest signing (`2D_wave_sim_V01_TemporaryKey.pfx`, thumbprint) and bootstrapper packages dropped; the `.pfx` was not copied. The PublishUrl confirms the author's own label for this build was V0.29.
- `Debug|x64` / `Release|x64` configurations (`Prefer32Bit=true`, `MinimumRecommendedRules.ruleset`) dropped; AnyCPU only.
- `AutoGenerateBindingRedirects`, `Deterministic` not set in the csproj. Project-level `OptionStrict Off` (every file opts in individually). Unused VB references `System.Data`, `System.Deployment`, `System.Xml`, `System.Xml.Linq`, `System.Data.DataSetExtensions`, `System.Net.Http`.
- Resources: VB references `Resources\QR-code.png` through `ResXFileRef`; the C# resx embeds a BinaryFormatter-serialised `Bitmap` (pixel-identical, 128×128) that will not load on .NET 10. `Form1.resx` stores a serialised `Icon` object instead of the raw `.ico` bytes. `AppIcon.ico` and `Wave_Dude_2D.ico` are byte-identical.
- `Application.myapp` values (`MySubMain`, `MainForm Form1`, `SingleInstance false`, `ShutdownMode 0`, `EnableVisualStyles`, `SaveMySettingsOnExit`) are hard-coded in `My\MyApplication.cs:35-49` and match. `Settings.settings` lost `UseMySettingsClassName` and the `(Default)` profile.
- Designer: 318/318 controls, all 229 `.Text` strings and all 209 `Handles`/`+=` wirings match. VB fields are `Friend WithEvents`; C# makes them `private`. The 950-odd VB designer separator comments are boilerplate, not author text.
- `ColorSchemeList/` (repo root) and `2D_wave_sim_V01/ColorSchemeList/`: 23 files, byte-identical.
